# CloudAct UI — Domain Migration Guide

This folder contains the main CloudAct React application (migrated from the
`cloudact-frontend-main` repo), prepared for deployment to a new domain while
continuing to use the existing backend API.

This repo now has three parts:

| Folder         | What it is                                      | Where it runs            |
| -------------- | ----------------------------------------------- | ------------------------ |
| `cloudact-ui/` | Main CloudAct React app (this folder)           | New domain (static host) |
| `frontend/`    | Plain HTML/JS chat UI for the calculator        | Vercel (existing)        |
| repo root      | Flask calculator + AI chat backend (`app.py`)   | Render (existing)        |

## What changed vs. the original repo

1. **Secrets removed from source.** `src/config.ts` no longer contains the
   Power BI `client_secret` / `client_id` / `tenant_id`. They are read from
   `REACT_APP_POWERBI_*` environment variables at build time. The old
   `src/.env` (which contained real credentials) was intentionally not copied.
   > ⚠️ The old credentials were committed to the original repo's history.
   > **Rotate the Power BI client secret in Azure AD** regardless.
2. **Backend URLs are overridable.** `REACT_APP_ENVIRONMENT` selects which API
   the UI talks to (LOCAL/DEV/QA/PROD); each URL can be overridden with
   `REACT_APP_API_URL_*`. Defaults match the original behavior.
3. **`REACT_APP_CALCULATOR_API_URL`** added for the Flask calculator/AI backend
   in this repo (not wired into any page yet — available via
   `CALCULATOR_API` in `src/config.ts`).
4. **`vercel.json`** added with an SPA rewrite so React Router routes
   (`/signIn`, `/createAccount`, `/dashboard`, …) work on page refresh.

## Run locally

```bash
cd cloudact-ui
cp .env.example .env        # fill in Power BI values if you need dashboards
npm install
npm start                   # http://localhost:3000
```

## Deploy to the new domain (Vercel)

1. In Vercel, create a new project from this GitHub repo.
2. Set **Root Directory** to `cloudact-ui` (framework preset: Create React App).
3. Set environment variables (Production):
   - `REACT_APP_ENVIRONMENT=PROD`
   - all `REACT_APP_POWERBI_*` values
4. Add the new domain under Project → Domains.

Any static host (S3+CloudFront, Netlify) works the same way — build with
`npm run build`, serve `build/`, and route all paths to `index.html`.

## Backend changes required for the new domain

The UI sends requests with `withCredentials: true` (`src/utils/axios.js`), so
the backend at `api.cloudforlawfirms.com` must explicitly allow the new origin:

- **CORS:** `Access-Control-Allow-Origin: https://<new-domain>` (exact origin,
  not `*`, because credentials are used) + `Access-Control-Allow-Credentials: true`.
- **Cookies:** auth cookies must be set with `SameSite=None; Secure` to be
  sent cross-site from the new domain.
- **OAuth redirect URIs:** add `https://<new-domain>/oauth/approval` to the
  Clio and Intuit (QuickBooks) app configurations, and the new domain to the
  Azure AD app for Power BI/MSAL.
- **Email links:** account-activation / password-reset emails generated by the
  backend must point at the new domain (`/confirm/activate`,
  `/activate/client/account`, `/resetpassword`).

## Pre-launch test checklist

- [ ] `/createAccount` → sign-up + activation email round trip
- [ ] `/signIn` → login sets cookies, lands on dashboard/home
- [ ] Refresh on a deep route (e.g. `/dashboard`) — no 404 (SPA rewrite works)
- [ ] Logout clears cookies and returns to `/signIn`
- [ ] Forgot/reset password flow
- [ ] Clio + QuickBooks OAuth connect from `/setupwizard`
- [ ] Reports generate and download
- [ ] Calculator pages save/load calculations
- [ ] No CORS errors in the browser console
- [ ] Built JS bundle contains no secrets (`grep -r "client_secret" build/` is clean)
