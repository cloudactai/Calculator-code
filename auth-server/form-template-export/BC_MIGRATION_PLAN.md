Two plan assumptions turned out to be wrong, both in our favour and against:

1. **The XFA flatten needs no Adobe and no manual step** (§4 is superseded). pdf.js
   renders XFA to positioned DOM; Chrome prints that DOM to a static Letter-size PDF
   with a real text layer. Better still, the rendered DOM carries the government's own
   field boxes, so Supreme overlays are read off exact geometry rather than detected
   from printed lines — the same quality as the Provincial AcroForm path. Tooling:
   `xfa/render.html` + `xfa/print_xfa.mjs` (CDP-driven), then `build_bc_supreme.py`.
2. **12 of the 32 Supreme forms are Adobe *interview* documents, not printable forms.**
   F1.1, F1.2, F3, F4, F5, F6, F31, F38, F45, F51, F51.1, F52 are data-entry wizards
   ("NOTE: All mandatory paragraphs will populate when form is previewed"); their blank
   layout is a questionnaire with internal plumbing fields (`TempStringName`,
   `Document Type Code`), and the filed document is generated by Adobe script at Preview
   time. Flattening the blank form — by any method, **including the manual Adobe
   print-to-PDF this plan originally chose** — produces the wrong document. These 12 are
   deferred; see "Remaining work" below.

**Also settled:** the federal "Registration of divorce proceedings" is an HTML form the
*court registry* submits to the Central Registry, not a PDF a lawyer fills. There is no
asset to import; it is out of scope rather than pending.

## 0. What already works (do NOT rebuild)

Province switching is **already wired end to end**:

- Matter creation already captures province.
- `auth-server` `/forms?province=XX&production_ready=true&mapping_ready=true`
  ([formsRoutes.js](../src/routes/formsRoutes.js) l.230) filters templates by the
  `province` column.
- The picker's `FormsArray` ([MatterFormData.jsx](../../cloudact-ui/src/utils/matterData/MatterFormData.jsx))
  now **groups by category dynamically** (fixed during the ON work), so any BC category
  renders as its own folder automatically.
- The overlay coordinate convention, editor, and `savePdf` stamping are province-agnostic.

**So adding BC = producing `FormXX.pdf` + `FormXX.json` overlays + `catalog.json` rows
with `province:"BC"`.** No frontend/province plumbing changes are required for the picker
to switch. (Prefill binds are the one BC-specific code touch — see §8, and it's deferred.)

### Locked decisions (2026-07-30)
- **One combined BC picker, no court-level selector.** Supreme and Provincial forms are
  distinct documents that never collide, so they all live in the single BC form set. The
  **court is kept in each category name** ("Supreme Court – …", "Provincial Court – …") so a
  lawyer can tell them apart and won't file the wrong court's form. `BCSC_`/`BCPC_` docId
  prefixes keep them distinct in storage.
- **XFA flatten = Adobe "Print to PDF"** (see §4). NOTE: this is a **manual step done outside
  this environment** — exactly like the two Ontario Word forms, which the *user* exported to
  PDF and dropped into `_incoming` (this box has no Adobe/Office renderer and headless XFA
  rendering isn't possible). Budget ~33 manual Adobe exports, or use the PDF Services API
  (§4 option 2) to automate.

## 2. CRITICAL finding — two very different source formats (verified by download)

| Source | Format | Verified sample | Pipeline |
|---|---|---|---|
| **Provincial Court** forms | **Standard fillable AcroForm** | Form 3 = 31pp/272 fields, Form 4 = 12pp/271, Form 44 = 1pp/27 — no XFA, renders fine | Same as ON's 17 fillable forms (extract widgets → overlay → flatten) |
| **Supreme Court** forms | **XFA dynamic (LiveCycle)** | F3/F8/F30/F51 all report 1 page, 0 AcroForm fields, `XFA=True`, classic layer = the Adobe **"Please wait… your PDF viewer may not be able to display this document"** placeholder; real content is a ~600 KB XFA packet | **Must flatten XFA → static PDF first** (see §4), then treat like ON's image/vector forms |
| **Federal** "Registration of divorce proceedings" | HTML page on justice.gc.ca (not a BC asset) | link is a page, not a PDF | fetch the actual PDF from justice.gc.ca separately |

**Why the XFA split matters:** our editor is pdf.js/react-pdf for display and **pdf-lib**
for fill/stamp (`savePdf`). pdf-lib cannot fill XFA, and react-pdf renders the "Please wait"
placeholder for XFA. (pdf.js *does* have an experimental `enableXfa` view mode, but it's
view-only and doesn't help the pdf-lib fill/flatten path — so flattening to static is the
correct choice for our architecture, not enabling XFA.)

## 3. Download strategy (how we fetch them, verifiably correct)

- Links in the docs are direct: `https://www2.gov.bc.ca/assets/download/<GUID>?forcedownload=true`.
  **All tested → HTTP 200, `application/pdf`.** curl works headlessly (no auth).
- Fetch into a gitignored staging dir `form-template-export/_incoming_bc/` (mirror the ON
  `_incoming/` pattern — importer never reads it).
- **Per-file verification (Test gate A):** `file --mime-type` = application/pdf; page count > 0;
  `sha256` + byte size recorded; the form's title/number text appears in the PDF (guards against
  a wrong GUID); capture the footer/edition date to confirm it's current.
- Build a **manifest.json**: `{docId, court, formNo, pfaCode, name, guid, url, sha256, bytes,
  pages, kind: acroform|xfa, catalogCategory}` — the single source of truth for the batch.
- Provincial forms with a second "see Note" link (F45/F18/F44): use the **first** (direct asset) link.
- Federal form: resolve the real PDF URL from the justice.gc.ca page, then same verification.

## 4. XFA flatten step (Supreme Court only)

> **SUPERSEDED 2026-07-30 — see STATUS above.** The flatten is fully headless via
> pdf.js + Chrome; no Adobe and no manual export were needed. The section below is kept
> for the reasoning about why pdf-lib cannot fill XFA, which still holds.

**Decision: flatten via Adobe "Print to PDF".** Flatten each XFA form to a **static,
non-interactive PDF** whose visible layout (all the empty field lines/boxes) becomes the printed
background.

> **This is a MANUAL step outside this environment.** Confirmed during the Ontario work: this box
> has no Adobe/Office renderer, and headless XFA rendering is not possible (pdf.js/pdfium/Chrome
> don't render XFA; GUI automation hung). The two Ontario Word forms were flattened by the **user**
> exporting them to PDF and dropping them in `_incoming`. The 33 Supreme forms need the same: open
> each in **Adobe Reader → File → Print → "Save as PDF"** (or Microsoft Print to PDF), producing a
> static multi-page PDF with a real text layer + vector lines and no AcroForm. Drop the results in
> `form-template-export/_incoming_bc/` named by docId (e.g. `BCSC_F8.pdf`).

Method options, in order:
1. **Adobe Reader → Print to PDF** (manual, one-time, most reliable) — the chosen path. ~33 exports.
2. **Adobe PDF Services API** (headless/scriptable "flatten") — automatable alternative if the manual
   count is too high; needs Adobe credentials. Offer this if the user prefers not to do 33 by hand.
3. **Research spike (lower confidence, optional):** parse the XFA template XML (`/AcroForm/XFA` packet)
   for `<field>` geometry to auto-place boxes. Works only for **fixed/"positioned"** layouts;
   **"flowed"** subforms reflow with no stable coordinates. A maybe-accelerator for simple forms only.

After flattening: **verify each renders in pdf.js** (open the static PDF — no "Please wait" page).
Then it has a text layer + vector graphics but no widgets → place overlay boxes via the
vector/text/table detection used for the Ontario Word forms.

> Before committing to flatten-everything, spend 15 min checking whether BC publishes a **static/
> "print" variant** of any Supreme form on the gov forms index — if so, prefer that over flattening.

## 5. Fillable-field pipeline (per form) — reuse the Ontario tooling

Overlay convention (proven, unchanged): `field.x` = left pt, `field.y` = top pt (y down),
`width/height` = points × **1.5**; `savePdf` stamps `y = pageH − field.y − height/scale`.
Reuse the scripts from the ON work (in the session scratchpad): `extract_fields.py`,
`generate_overlays.py`, `build_docx_forms.py` (box/checkbox/underline/table detectors),
`sig_detect.py`, `rebuild_catalog.py`.

- **Provincial (AcroForm):** decrypt (empty pw) → read each widget `/Rect`+type+name → convert to
  overlay convention → strip `/AcroForm` + widget annots to a clean printed background (0 native
  fields, matching the repo) → boxes land exactly on the government's own fillable spots. Auto-bind
  deferred (see §8).
- **Supreme (flattened static):** no widgets → detect boxes via `cluster_drawings()`, checkboxes via
  the ☐ glyph, blank lines via dotted-underline detection, and grids via table-cell detection.
- **Checkbox completeness:** detect **every** printed square/glyph and add a `CheckBox` (the Form 8A
  lesson — the old mapper missed page-1/2 checkboxes).
- **Overlap guard (automated):** after placement, flag any field whose box overlaps a printed text
  baseline (label) and nudge it down one line + shrink height (the Form 25 / 25H lesson). Add this as
  a reusable check, not a manual pass.

## 7. docId / category / sortOrder scheme (no collisions)

- **docId** (also the PDF filename base and stamped field-name prefix — must be globally unique &
  filesystem-safe; dots → underscores):
  - Supreme: `BCSC_F<num>` → `BCSC_F8`, `BCSC_F1_1`, `BCSC_F51_2`.
  - Provincial: `BCPC_<formNo>` → `BCPC_3`, `BCPC_4`, `BCPC_44` (keep the `PFA###` code in
    `footerText`/notes). Form numbers are unique within Provincial.
  - Prefixes guarantee no clash with Ontario `FormNN` or between the two BC courts.
- **province:** `"BC"` for all.
- **category** (the dynamic picker renders these as folders — encode **court + function** so a BC
  lawyer sees the court split): e.g. `Supreme Court – Applications`, `Supreme Court – Financial`,
  `Supreme Court – Orders`, `Supreme Court – Conferences`, `Supreme Court – Notices`,
  `Supreme Court – Discovery`, `Supreme Court – Trial`, `Supreme Court – Divorce`,
  `Supreme Court – Requisitions`; `Provincial Court – Applications`, `Provincial Court – Financial`,
  `Provincial Court – Orders`, `Provincial Court – Notices`, `Provincial Court – Trial`,
  `Provincial Court – Filing`. (Final category assignment per form in Appendix A.)
- **sortOrder:** only orders *within* a province (API filters by province, picker groups by category
  preserving order). Give BC its own contiguous block; order by court then category then form number.

## 8. Prefill / binds (BC vocabulary) — phased, deferred

BC headings differ from Ontario: Supreme uses **Claimant(s)/Respondent(s)**, **Court File No.**,
**Registry**; Provincial uses Applicant/Respondent + registry/location. The current
`buildPrefillData` is Ontario-shaped (`court_info.courtFileNumber`, `applicant.*`, `respondent.*`,
`applicantsLawyer.*`, `respondentsLawyer.*`).

- **Phase 1 (this project):** correct editable boxes on every blank + signatures skipped, **no binds**
  (editable-only) — same priority ladder as Ontario's first pass. Forms are fully usable.
- **Phase 2 (later, PREFILL track):** add BC heading binds. Requires (a) confirming which fields BC
  matters actually capture, (b) a BC branch in `buildPrefillData` mapping claimant→applicant, registry,
  file-no, etc., (c) resolver verification. The resolver is province-agnostic (it reads bind paths from
  the document's own map), so only the data object needs the right roots.

## 9. Deploy without breaking Render — **infra work to do FIRST** (blocking prerequisite)

**Observed problem:** `start` = `prisma migrate deploy && node scripts/bootstrap-forms.js && node
server.js`. The bootstrap **blocks** server start and, on any checksum drift, re-imports the **whole
catalog** one process per template (~11 s each). Importing 45 ON forms already **timed out Render's
port scan** once (server never bound a port; an import also hung ~10 min). With ~89 forms this will
**reliably fail**.

**Required changes before landing BC forms:**

1. **Import only new/drifted templates.** In `bootstrap-forms.js`, when drift/new is detected, invoke
   the importer with the **specific docIds** (extend `import-form-templates.js --doc-id` to take a
   comma list, or loop). Steady-state deploys then re-import only what changed → seconds.
2. **Bind the port first; bootstrap in the background.** Change `start` to
   `prisma migrate deploy && node server.js`; in `server.js`, right after `app.listen()`, spawn the
   forms bootstrap as a **detached background child** (or run async, non-awaited). Render sees an open
   port in seconds regardless of form count; forms appear a few minutes later.
3. **Harden the importer:** per-form `try/catch`, a per-form **timeout** (kill + continue on hang),
   idempotent upsert (already present), one clear log line per import.
4. **First bulk load (44 forms):** after 1–3, either (a) let the background bootstrap import them
   post-deploy while watching logs, or (b) run `npm run forms:import:render-safe` once in the Render
   Shell. Prefer (a) with monitoring; (b) as fallback.
5. **Batch the pushes:** land BC forms in small batches (10–15). Each deploy's incremental import is
   bounded and failures localize. Push → watch logs (port binds fast; "imported" lines) → verify
   `/forms?province=BC` count grew → next batch.
6. **Keep `_incoming_bc/` out of git;** commit only `FormXX.pdf/json` + `catalog.json` + `audit.json`.

**Acceptance:** deploy binds a port within ~30 s; logs show only changed forms importing; no
port-scan timeout; app stays up on the old version until the new one is healthy.

## 10. Testing plan (thorough) — gates A–M, each a scripted check

- **A. Source integrity:** valid PDF (mime + magic), pages > 0, title/number text present, footer/edition
  captured, sha256 + bytes recorded in manifest.
- **B. Format classification:** AcroForm field count vs XFA flag; XFA → routed to flatten; assert every
  Supreme form is flattened & no longer shows the "Please wait" text.
- **C. Geometry/bounds:** no field outside page bounds (±2 pt); no duplicate `id`; positive w/h; valid
  page indices. (Reuse the ON bounds check.)
- **D. Signature skip:** 0 boxes above any "Signature" caption; date-of-signature boxes kept; per-form audit.
- **E. Visual QA:** render **every page** at 2× with overlay boxes (blue=bound, orange=editable, red=checkbox);
  build a per-form **contact sheet**; eyeball: every blank boxed, checkboxes on squares, tables gridded,
  no giant overlapping boxes, clean flattened background.
- **F. Overlap check (automated):** flag fields overlapping printed-text baselines → must be nudged.
- **G. Resolver/prefill:** run `prefillFields` over each map; Phase 1 has no binds → asserts no dead binds;
  Phase 2 → asserts every bound heading field resolves with sample BC data.
- **H. Catalog integrity:** `npm run forms:validate-export` (dry-run import) passes; every catalog row has
  pdf+json on disk; `province:"BC"`; unique `sortOrder`; category set; audit `excluded:0`.
- **I. Province-filter API:** after import into a local/staging DB, `/forms?province=BC…` returns exactly
  the BC set grouped right; `/forms?province=ON…` still returns only the 45 ON forms (no cross-leak).
- **J. Picker UI:** unit-test `FormsArray` with a BC fixture → BC folders; ON matter shows ON, BC matter
  shows BC. Manual: create BC matter → picker shows Supreme/Provincial folders → create a form → editor
  shows aligned boxes, signatures absent, and (Provincial multi-page) all pages render.
- **K. Deploy smoke:** post-deploy, port binds fast (no timeout); logs import only the batch; `/forms?
  province=BC` count correct; open one BC form end-to-end (view → fill → Save → Download).
- **L. Regression:** ON `FormNN.*` checksums unchanged; ON matter picker unchanged; existing saved
  documents still load (mapping read live from templateVersion).
- **M. Per-form acceptance table:** form, court, pages, fields, checkboxes, signatures-skipped, bounds-ok,
  visual-ok, imported-ok — all green before "done".

## 12. Risks & mitigations

- **Supreme XFA unusable in pdf.js** → flatten to static first (biggest effort/risk; §4).
- **Render deploy timeout** → infra change is a hard prerequisite (§9), not optional.
- **Dynamic XFA reflow** → a static snapshot may paginate differently than Adobe would when filled;
  acceptable since we fill a flat overlay. Verify page count post-flatten.
- **docId collisions** → `BCSC_`/`BCPC_` prefixes.
- **Gov version drift** → manifest sha256 + footer/edition; re-download check before each batch.
- **Federal form + a couple links without `?forcedownload`** → still 200; handle case-by-case.
- **Provincial forms are large** (Form 3 = 31 pp/272 fields; Form 4 = 12 pp/271) → many fields; extraction
  scales, but visual QA is heavy — rely on contact sheets + automated bounds/overlap checks.
